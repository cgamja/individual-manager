# 같은 창 레벨 안의 순서는 클릭할 때마다 바뀐다 — 순서가 아니라 레벨로 잡는다

**겪은 날**: 2026-09-01 (핀볼 판, `feat/f3-pinball-field-01`)
**건드린 곳**: `src-tauri/src/pet_bridge.rs`의 `create_field_window`·`sink_field_below_pets`

## 증상

핀볼 모드를 켜면 화면 전체를 덮는 투명 창("판")이 깔린다. 판은 **펭귄 창보다 아래**에
있어야 펭귄 클릭·드래그가 지금까지처럼 동작한다.

만들 때 펭귄 창을 앞으로 올려 두었는데, **잠깐은 맞다가 곧 어긋났다.** 증상은
"펭귄을 클릭해도 안 날아간다" 하나뿐이라 원인이 창 순서라는 게 안 보였다. 아무것도
실패하지 않고, 로그도 깨끗하고, 창은 전부 제자리에 있었다.

## 안 통한 시도

| 시도 | 왜 안 되나 |
|---|---|
| 판을 만든 뒤 펭귄 창에 `set_always_on_top(true)` 다시 걸기 | 이미 참이라 창 레벨을 다시 세팅하지 않는다. 아무 일도 안 일어난다 |
| `set_always_on_top(false)` → `(true)`로 껐다 켜기 | 그 순간에는 앞으로 온다. 하지만 **다음 클릭에 다시 뒤집힌다** |
| `ns_window()` + `orderFrontRegardless` | 위와 같다. 앱이 비활성일 때도 동작하는 올바른 호출이지만, **한 번 올려 두는 것**이라는 성질은 같다 |

세 시도가 전부 같은 착각 위에 있었다: **"한 번 올바른 순서로 만들어 두면 유지된다."**

유지되지 않는다. 판을 클릭하는 순간 판이 맨 앞으로 온다. 그리고 이 기능에서는
**사용자가 판을 반드시 클릭한다** — Esc를 누르려면 판에 포커스가 있어야 하기 때문이다.
그래서 "고쳤다"고 확인한 직후의 다음 조작에서 곧바로 깨졌다.

## 해결

**순서를 잡지 말고 레벨을 나눈다.** 판의 `NSWindow` 레벨을 펭귄보다 한 칸 낮춘다.

```rust
// NSFloatingWindowLevel(3) 바로 아래
const FIELD_WINDOW_LEVEL: isize = 2;
unsafe { (&*(ptr as *const NSWindow)).setLevel(FIELD_WINDOW_LEVEL) };
```

| 레벨 | 창 |
|---|---|
| 24 (`NSMainMenuWindowLevel`) | 메뉴바 — 트레이 아이콘이 여기 있다 |
| 3 (`NSFloatingWindowLevel`) | 펭귄 (`always_on_top`) |
| **2** | **핀볼 판** |
| 0 (`NSNormalWindowLevel`) | 다른 앱들 |

## 왜 통하는가

**레벨은 클릭으로 바뀌지 않는다.** macOS의 창 정렬은 두 단계다 — 먼저 레벨로 나누고,
같은 레벨 안에서만 순서를 다툰다. 클릭·`orderFront`·포커스는 **뒤쪽만** 건드린다.
레벨을 다르게 두면 사용자가 무엇을 하든 순서가 뒤집힐 수 없다.

레벨 2를 고른 것도 계산이다. 펭귄(3)보다 낮아 클릭이 펭귄에게 가고, 보통 창(0)보다
높아 다른 앱 위에서도 커서가 방망이로 보이며, 메뉴바(24)보다 한참 낮아 **트레이
아이콘이 그대로 눌린다** — 화면 전체의 클릭을 먹는 기능이라 그게 나가는 문이다.

## 예방책

- **"창 순서"가 요구사항에 나오면 레벨로 옮겨 적을 수 있는지 먼저 본다.** 순서로
  풀어야만 하는 경우는 드물고, 순서로 푼 것은 사용자의 다음 클릭에 깨진다.
- **한 번만 실행되는 배치 코드로 지속적인 성질을 만들지 않는다.** 창 생성 시점에
  거는 모든 것이 이 함정 후보다.
- 이 부류는 **테스트로 안 잡힌다.** 두 러너와 타입 검사가 전부 통과했고 로그도
  깨끗했다. 창 순서를 바꾸는 변경은 **실제로 클릭해 봐야** 한다. 특히 "고친 직후"가
  아니라 **다른 창을 한 번 클릭한 뒤에** 확인한다.

## 곁가지 — 판 하나로 여러 화면을 덮으려던 것

처음에는 모든 화면의 합집합을 구해 **창 하나**로 덮으려 했다. 화면마다 배율이 다르면
논리 좌표의 단위가 화면마다 달라지는데 **창 하나는 배율 하나만 쓴다** — 그래서 한쪽
화면에서만 맞았다. **화면마다 창을 따로 만들면** 각 창이 자기 화면의 배율만 쓰므로
문제가 사라진다 (`pinball-field-<번호>`).

여기서도 증상은 "다른 화면에서 커서가 안 바뀐다" 하나였고, 원인(배율)이 증상에서
전혀 안 보였다. **화면을 넘나드는 좌표는 항상 배율부터 의심한다.**
