# 무엇을 테스트하고 무엇을 손으로 확인하는가

이 앱은 자동 테스트로 잡히는 영역과 안 잡히는 영역의 경계가 뚜렷하다. 순수 로직은 전부 테스트로
잡히고, OS 통합 표면(트레이·창·알림)은 거의 안 잡힌다. 그 경계를 모르면 테스트를 다 통과시켜
놓고도 앱이 안 뜨거나, 반대로 테스트할 수 없는 걸 테스트하려다 시간을 태운다.

## 테스트 대상 우선순위 (CONVENTIONS.md)

**1순위 — 반드시 단위 테스트.** 순수 로직: 상태 전이, 동기화 검증·재시도 큐, 상태 4단계 전환,
키워드 필터, 시간 계산, 포맷팅. 시간·난수·네트워크는 인자로 주입해서 테스트가 제어할 수 있게
설계한다. `pomodoro.rs`가 `now`를 인자로 받는 게 그 예다.

**2순위 — 반드시 단위 테스트, 단 실제 호출은 금지.** 외부 API 연동(Notion/Jira/Calendar/Slack/
Webex)은 mock/fixture로만 테스트한다. 성공 응답 파싱뿐 아니라 **에러 경로를 반드시 포함**한다:
토큰 만료, rate limit(429), 네트워크 실패, 예상과 다른 스키마, 빈 결과, 페이지네이션.
실무에서 깨지는 건 대부분 이쪽이다.

**3순위 — 선택.** UI 컴포넌트. 상태별 렌더링 분기처럼 로직이 있으면 쓰고, 순수 표시라면
수동 확인으로 대체해도 된다.

**테스트하지 않는 것.** 트레이 생성, 창 표시/숨김, 포커스, 알림 발송, Dock 정책 — OS가 실제로
동작해야 검증되는 영역이다. 플랜에는 `Test expectation: none — OS 통합 표면`이라고 명시하고
아래 수동 체크리스트로 넘긴다.

## 테스트 작성 규칙

이름은 한국어로 **동작**을 서술한다. 상태나 함수 이름이 아니라 "무엇을 하면 무엇이 된다"로.

```rust
#[test]
fn 일시정지_후_재개하면_남은_시간이_보존된다() { ... }
```

```ts
it("동기화 검증에 실패하면 전체 재동기화를 수행한다", () => { ... });
```

프론트에서 Rust 커맨드를 부르는 래퍼는 `@tauri-apps/api/mocks`의 `mockIPC`로 테스트한다
(`src/lib/timer.test.ts` 참고). 픽스처에 실제 토큰·워크스페이스 ID·개인 데이터를 넣지 않는다.

## 실행

```bash
npm test                      # 프론트 (vitest run)
cd src-tauri && cargo test    # Rust
```

**둘 다 돌린다.** 러너가 분리돼 있어서 한쪽만 보고 "전체 통과"로 착각하기 쉽다.

## 수동 체크리스트 — 메뉴바 셸을 건드렸을 때

`src-tauri/src/lib.rs`(트레이·창 이벤트·정책)나 창 표시/숨김 경로를 수정했다면
`npm run tauri dev`로 실제로 돌려서 확인한다.

- [ ] 트레이 펭귄 아이콘이 메뉴바에 뜬다
- [ ] 좌클릭으로 팝오버가 아이콘 아래에 열린다
- [ ] 팝오버가 열린 상태에서 좌클릭하면 닫힌다 (다시 열리지 않는다 — 토글 경쟁)
- [ ] 바깥을 클릭하면 팝오버가 닫힌다
- [ ] **팝오버를 닫은 뒤에도 트레이 아이콘이 남아 있다** ← 과거에 실제로 깨졌던 항목
- [ ] Dock에 앱 아이콘이 없다
- [ ] 우클릭 메뉴의 "종료"가 동작한다
- [ ] 팝오버 배경이 투명하게 렌더링된다 (흰 사각형이 아니다)

## 수동 체크리스트 — 주기 작업·알림을 추가했을 때

- [ ] 팝오버를 닫고 **5분 이상** 방치한 뒤 열었을 때 상태가 정확하다
      (숨겨진 웹뷰의 JS 타이머는 정지한다 — 진실 원천이 타임스탬프이고 틱을 Rust가 소유하는지 확인)
- [ ] 팝오버가 닫힌 상태에서도 트레이 타이틀이 갱신된다

알림은 **`npm run tauri dev`에서 오지 않는 것이 정상이다.** dev 바이너리는 번들 ID가 등록된
앱이 아니라 macOS가 거부한다. 검증은 번들로만:

```bash
npm run tauri build
open src-tauri/target/release/bundle/macos/penguin.app
```

- [ ] 번들 앱에서 이벤트 발생 시 macOS 알림이 도착한다
- [ ] 알림 권한을 거부해도 앱이 정상 동작한다 (대체 표시로 폴백)

## 자주 놓치는 것

- **Tauri 플러그인 추가는 네 곳**: `src-tauri/Cargo.toml`, `package.json`, `lib.rs`의 `.plugin(...)`,
  프론트에서 호출한다면 `src-tauri/capabilities/default.json`의 `permissions`.
  capabilities를 빠뜨리면 컴파일은 되고 런타임에 권한 오류가 난다.
- **`app.hide()`를 쓰지 않는다** — macOS 26(Tahoe)에서 트레이 아이콘이 사라진다.
- **틱 스레드에서 트레이를 직접 조작하지 않는다** — `run_on_main_thread`로 감싼다.
- **상태를 바꾸는 커맨드는 먼저 만료를 정산한다** — 1Hz 틱과 사용자 조작이 만료 시점에서
  경쟁해 이벤트가 유실될 수 있다 (`timer_bridge.rs`의 `settle_finished` 패턴).

배경과 근거는 `docs/solutions/best-practices/tauri-v2-macos-menubar-app-pitfalls.md`에 있다.
