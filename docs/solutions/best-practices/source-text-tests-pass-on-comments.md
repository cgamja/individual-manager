# 소스 텍스트를 읽는 검사는 주석에 걸려 헛돈다

> **한 줄 요약** — `readFileSync`로 소스를 읽어 이름을 찾는 검사는, **찾는 이름이
> 주석에 남아 있으면** 실제 코드를 지워도 초록불을 준다. 이 레포는 주석에 실패
> 이력을 길게 남기는 것이 규범이라 그 위험이 상시적이다.

## 왜 이 문서가 있나

이 레포의 다른 두 학습 기록이 **같은 처방**을 내린다:

- `ui-bugs/duplicate-keyframes-silently-kills-animation.md` 예방 §3 — *"소스를 직접
  대조하는 테스트를 만든다"*
- `best-practices/tauri-command-registration-silent-failure.md` — 등록 누락을
  소스 대조로 잡으라는 같은 취지

그 처방을 따라 만든 검사가 **바로 그 처방 때문에 헛돌았다.** 처방 자체의 결함이므로
따로 적는다.

## 증상

에셋 리팩터링(2026-09-03)에서 커서 방망이를 각 창이 심게 만들고, 심는 걸 빠뜨리면
커서가 안 바뀌므로 검사를 붙였다.

```ts
expect(entry).toContain("installBatCursor()");
```

`src/pinball/main.ts`의 호출을 **주석 처리해도 초록이었다.**

```ts
// installBatCursor();   ← 커서가 영영 안 심긴다. 검사는 통과한다.
```

두 러너(`npm test` 328개 · `cargo test` 423개), 타입 검사(`npm run build`), 번들
빌드가 전부 통과한다. 증상은 "핀볼을 켜도 커서가 그대로다" 하나뿐이다.

**반대 방향도 있다.** 마크업에서 지운 클래스가 주석에 남아 있으면 "아직 쓰인다"로
집계되고, 주석에만 등장하는 이름이 "CSS 규칙이 있어야 하는 클래스"로 등록된다.

## 안 통한 시도

- **더 긴 문자열을 찾기** — `"installBatCursor();"`처럼 세미콜론까지 넣어도
  주석 안의 그것과 똑같다.
- **`expect(...).toContain` 대신 정규식** — 문자열이든 정규식이든 **주석과 코드를
  구분하지 못한다**는 성질이 그대로다.
- **호출 위치를 안 보고 존재만 확인하기** — 함수 안에 감싸 두면(`function 죽은코드()
  { installBatCursor(); }`) 아무도 안 부르는데 이름은 남는다. 이것도 통과했다.

## 해결

**비교 전에 주석을 걷어낸다.** TS·JS·CSS 전부.

```ts
const 코드만 = (s: string) =>
  s.replace(/\/\*[\s\S]*?\*\//g, " ").replace(/\/\/.*/g, " ");
```

CSS는 `//` 주석이 없으므로 블록만 지우면 된다. **이 레포는 이미 여러 곳에서 그렇게
하고 있었다** — `volley.test.ts`의 `공은_자기_창에만_묶인다`, `pet-css.test.ts`의
`움직임 감소` 블록이 그렇다. 안 하는 곳만 골라 맞추는 일이었다.

호출 **위치**까지 봐야 하면 들여쓰기 없는 줄로 못 박는다.

```ts
expect(코드만(entry)).toMatch(/^installBatCursor\(/m);
```

## 왜 통하는지

`readFileSync`가 주는 것은 **텍스트일 뿐 코드가 아니다.** 파서를 붙이지 않는 한
"이 이름이 실행되는 자리에 있나"는 대답할 수 없고, 주석 제거는 그 질문에 가장 싸게
근사하는 방법이다. 완벽하지는 않다 — 문자열 리터럴 안의 이름은 여전히 걸린다.

**그래서 더 나은 길은 텍스트를 아예 안 보는 것이다.** 같은 리팩터링에서
`훌라_차림은_pg_all_안에_있다`는 소스의 등장 순서 비교(`indexOf`)를 버리고
**렌더한 DOM에서 `.pg-all`이 `.pg-luau`를 품는지**로 바꿨다. 파일 배치와 무관해졌고,
테스트 이름이 원래 말하던 것을 그대로 검사하게 됐다. 텍스트 대조는 **DOM이나 실제
호출을 볼 수 없을 때의 차선책**이다.

## 예방책

1. **소스 대조 검사를 새로 쓰면 반드시 돌연변이로 한 번 빨갛게 만들어 본다.**
   지키려는 대상을 지우거나 주석 처리하고 러너를 돌린다. 초록이면 그 검사는 없는
   것과 같다. 이 레포의 실제 사례에서는 검사 열다섯 개 중 **일곱 개가 헛돌았고**,
   전부 이 방법으로만 드러났다.
2. **되돌릴 때 `git checkout <파일>`을 쓰지 않는다.** 커밋 전 작업이 통째로
   날아간다 — 실제로 그렇게 한 유닛의 변경을 잃었고, 테스트가 초록이라 한참 뒤에
   알았다. `cp`로 복사해 두고 되돌린다.
3. **가능하면 텍스트 대신 렌더된 DOM이나 실제 호출을 본다.**
4. **주석 안에 검사가 찾는 문자열을 적지 않는다** — 걷어내기를 빠뜨린 검사가 하나만
   있어도 터진다. 이 문서를 쓰는 동안에도 `pinball-css.test.ts`의 새 검사가 내가
   그 파일에 적어 둔 **설명 주석**에 걸렸다. 고치고 있는 버그에 고치는 사람이 걸렸다.
